# GradNavi Team Members and Roles

Status: Team roles and implementation responsibilities aligned with the revised Microsoft Project schedule.

## Source of Truth

The GradNavi Microsoft Project schedule is the authoritative planning record for task ownership, Sprint allocation, sequencing, dependencies, and milestones.

This document describes each member's high-level project role and summarises their scheduled implementation responsibilities.

Detailed task ownership is maintained in:

    docs/project-management/task-leads.md

Detailed WBS tasks and dependencies are maintained in:

    docs/project-management/work-breakdown-structure.md

Requirement implementation mapping is maintained in:

    docs/requirements/requirements-assignment-matrix.md

A member's high-level role does not give ownership of every task within the same technical area.

The WBS task owner recorded in Microsoft Project remains accountable for the assigned implementation task.

## Supporting Work

A team member may support another member's assigned task through:

- Code review.
- API testing.
- Integration.
- Debugging.
- Documentation.
- Security review.
- Frontend or backend support.
- Deployment verification.
- Test evidence.
- Pull request review.

Supporting work does not transfer task ownership.

## Task Ownership Rule

The task lead recorded in Microsoft Project remains accountable for the assigned task.

The high-level roles of Frontend Lead, Backend Lead, and Full-Stack Developer describe each member's broader project function.

They do not override individual WBS assignments.

## Ownership Change Rule

Any approved ownership change must first be recorded in Microsoft Project.

The team must then update:

1. `docs/project-management/work-breakdown-structure.md`
2. `docs/project-management/task-leads.md`
3. `docs/project-management/responsibility-matrix.md`
4. `docs/project-management/product-backlog.md`
5. `docs/requirements/requirements-assignment-matrix.md`
6. `docs/02-team-members-and-roles.md`
7. Trello
8. Relevant GitHub records
9. Meeting minutes
10. Contribution records

The Microsoft Project schedule remains the authoritative implementation-planning record.
