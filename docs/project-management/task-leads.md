# GradNavi Task Leads

## Source of Truth

The GradNavi Microsoft Project schedule is the authoritative source for task ownership.

This document mirrors the Owner field recorded in Microsoft Project.

Supporting members may contribute to a task through implementation, review, integration, testing, or documentation. Supporting work does not change the assigned task owner unless the team approves an ownership change and updates the Microsoft Project schedule.

Any ownership change should also be reflected in:

- Microsoft Project.
- Work Breakdown Structure.
- Trello.
- GitHub issues or project items where applicable.
- Meeting minutes.
- Contribution records.

## Lead Responsibilities

The assigned task lead is responsible for:

1. Confirming the task scope.
2. Confirming task dependencies before implementation.
3. Coordinating required supporting work.
4. Tracking blockers.
5. Maintaining completion evidence.
6. Ensuring the task meets its acceptance criteria.
7. Presenting completed work for team review where required.
8. Updating Trello and related project-management records.
9. Ensuring GitHub branches, commits and pull requests are linked where applicable.

## Supporting Contributions

Team members may support tasks outside their assigned ownership.

Examples include:

- Code review.
- Frontend and backend integration.
- API testing.
- Security testing.
- Documentation.
- Defect investigation.
- Pull request review.
- User acceptance testing.
- Deployment verification.

A supporting contribution does not transfer ownership of the task.

## Ownership Change Rule

The team must approve changes to task ownership.

An approved ownership change should be recorded in:

1. Microsoft Project.
2. `docs/project-management/work-breakdown-structure.md`.
3. `docs/project-management/task-leads.md`.
4. Trello.
5. Relevant GitHub issue or project item.
6. Meeting minutes.
7. Contribution records.

The Microsoft Project schedule remains the authoritative planning record.
